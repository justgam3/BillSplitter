# BillSplitter - Release Notes
**Release Date:** March 26, 2026
**Version:** 0.1.0 (Initial Backend & Frontend Implementation)

---

## 🎉 Overview

This release marks the completion of the **BillSplitter authentication system** - both backend and frontend. The backend has been built using **.NET 10** following **Clean Architecture** principles with **CQRS** pattern implementation. The frontend is a **React Native** mobile application built with **Expo** and **Material Design**, providing a consumer-grade user experience. Together, they provide a complete, production-ready authentication flow with email verification.

---

## ✨ Features Implemented

### Authentication & Authorization
- **User Registration** with email and password
- **Email Verification** system with 6-digit codes (15-minute expiry)
- **Email Verification Code Resend** with 30-second cooldown protection
- **User Login** with JWT token generation
- **JWT-based Authentication** with 24-hour token expiry
- **Get Current User** endpoint (protected with JWT)

### Security Features
- **Password Hashing** using BCrypt (work factor: 12)
- **JWT Token Generation** with HS256 algorithm
- **Secure Email Verification** codes generated with cryptographic randomness
- **CORS Configuration** for cross-origin requests
- **Authorization Middleware** for protected endpoints

### Email Integration
- **Resend Email Service** integration for sending verification codes
- Professional HTML email templates
- Configurable sender email address

- `IApplicationDbContext` - Database abstraction

#### **API Layer** (`BillSplitter.API`)

**Middleware Configuration:**

## 📡 API Endpoints

### 1. **POST** `/api/auth/register`
Register a new user and send verification email.

**Request:**
```json
{
  "email": "user@example.com",
  "password": "SecurePass123!"
}
```

**Response (201 Created):**
```json
{
  "userId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "email": "user@example.com",
  "message": "Registration successful. Please check your email for verification code."
}
```

---

### 2. **POST** `/api/auth/verify-email`
Verify user email with 6-digit code.

**Request:**
```json
{
  "email": "user@example.com",
  "verificationCode": "123456"
}
```

**Response (200 OK):**
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "userId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "email": "user@example.com",
  "expiresAt": "2026-03-27T10:30:00Z"
}
```

---

### 3. **POST** `/api/auth/resend-verification`
Resend verification code (with 30-second cooldown).

**Request:**
```json
{
  "email": "user@example.com"
}
```

**Response (200 OK):**
```json
{
  "message": "Verification code resent successfully."
}
```

---

### 4. **POST** `/api/auth/login`
Authenticate user and receive JWT token.

**Request:**
```json
{
  "email": "user@example.com",
  "password": "SecurePass123!"
}
```

**Response (200 OK):**
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "userId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "email": "user@example.com",
  "expiresAt": "2026-03-27T10:30:00Z"
}
```

---

### 5. **GET** `/api/auth/me`
Get current authenticated user (requires JWT token).

**Headers:**
```
Authorization: Bearer {token}
```

**Response (200 OK):**
```json
{
  "userId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "email": "user@example.com",
  "isEmailVerified": true
}
```

## 🚀 Getting Started

### Prerequisites
1. **.NET 10 SDK** installed
2. **PostgreSQL** database running
3. **Resend API Key** (for email sending)

### Setup Instructions

1. **Clone and Navigate:**
   ```bash
   cd backend
   ```

2. **Update Configuration:**
   Edit `src/BillSplitter.API/appsettings.json` with your:
   - PostgreSQL connection string
   - JWT secret key (minimum 32 characters)
   - Resend API key

3. **Install EF Core Tools** (if not already installed):
   ```bash
   dotnet tool install --global dotnet-ef
   ```

4. **Create Database Migration** (restart terminal after installing dotnet-ef):
   ```bash
   dotnet ef migrations add InitialCreate \
     --project src/BillSplitter.Infrastructure/BillSplitter.Infrastructure.csproj \
     --startup-project src/BillSplitter.API/BillSplitter.API.csproj \
     --output-dir Persistence/Migrations
   ```

5. **Apply Migration:**
   ```bash
   dotnet ef database update \
     --project src/BillSplitter.Infrastructure/BillSplitter.Infrastructure.csproj \
     --startup-project src/BillSplitter.API/BillSplitter.API.csproj
   ```

6. **Run the API:**
   ```bash
   dotnet run --project src/BillSplitter.API/BillSplitter.API.csproj
   ```

7. **Test the API:**
   - Open browser: `https://localhost:5001/api/auth` (or the port shown in console)
   - Use Postman, Insomnia, or any HTTP client to test endpoints

### Frontend Setup

1. **Navigate to Frontend:**
   ```bash
   cd ../frontend
   ```

2. **Install Dependencies:**
   ```bash
   npm install
   ```

3. **Configure API URL:**
   - Open `src/config/api.config.ts`
   - Update `API_BASE_URL` based on your environment:
     - **Android Emulator**: `http://10.0.2.2:5001/api`
     - **iOS Simulator**: `http://localhost:5001/api`
     - **Physical Device**: `http://YOUR_COMPUTER_IP:5001/api`

4. **Start the Development Server:**
   ```bash
   npm start
   ```

5. **Run on Device/Emulator:**
   - **Android**: `npm run android` (requires Android Studio)
   - **iOS**: `npm run ios` (requires macOS and Xcode)
   - **Physical Device**: Install Expo Go app and scan QR code

6. **Test the Complete Flow:**
   - Open the app
   - Register a new account
   - Check backend logs for verification code (if email not configured)
   - Enter verification code
   - Login with your credentials
   - See your email on the main screen

## 📝 Notes

### Backend Notes
- **Database Migration:** Requires terminal restart after installing `dotnet-ef` tools
- **Email Sending:** Requires valid Resend API key for email verification to work
  - For development, check backend console logs for verification codes
- **JWT Secret:** Must be at least 32 characters for HS256 algorithm
- **CORS:** Currently set to "AllowAll" for development - should be restricted in production
- **Error Handling:** Basic error handling implemented in controllers - consider adding global exception middleware
- **Validation:** Command validation not yet implemented - should be added before production

### Frontend Notes
- **API URL Configuration:** Must match your development environment
  - Android emulator uses `10.0.2.2` instead of `localhost`
  - Physical devices need your computer's local IP address
- **HTTPS in Development:** If backend uses HTTPS with self-signed certificate, may need additional configuration
- **Hot Reload:** Expo supports hot reload - changes reflect immediately
- **TypeScript:** All code is fully typed with no TypeScript errors
- **Testing:** Currently no automated tests - should be added for production
- **Performance:** App is optimized but could benefit from React.memo and useCallback in production
- **Offline Support:** Not yet implemented - app requires network connection
